# Web 设置入口统一验收（2026-09-17）

## 入口与范围

- `misaka web`：真实终端中进入设置菜单；重定向或管道中保留只读状态输出。
- `misaka web configure`：明确进入菜单，非终端环境给出脚本配置入口。
- `misaka setup web` 和完整 `misaka setup` 的 Web 步骤：复用同一个菜单，不再维护固定的另一份后端列表。
- `--profile DIR` 编辑该角色覆盖文件；默认编辑共享 Web 配置。
- 原有 `status/providers/setup/set/unset/enable/disable/accounts/login/logout/browser-*/gateway-*` 保留。
- 此次补齐的是 setup 的 **Web 部分**，没有改动其他 setup 章节的业务逻辑。

## 修正的旧行为

1. 原 setup 只配置共享 backend，已有 search_backend 可以继续覆盖它，出现“保存了但实际没切换”。新菜单直接写目标 capability。
2. 原 setup 用固定列表要求密钥，遗漏现有免费档位、浏览器和多项配置。现复用 registry schema。
3. 原 setup 总把 Web 总结标成成功。现明确只做本地配置检查，不宣称网络可用或付费权限已通过。
4. 角色层清空选择时，旧 writer 会产生空名称的 provider tier；增加非空判断，避免写入空提供方配置。
5. 所有菜单保存先做本地校验及确认；不覆盖损坏 JSON。按确认动作分别保存，后续取消不会回滚之前明确保存的操作。
